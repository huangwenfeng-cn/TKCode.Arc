# 视觉验收

先读 [实施指南](../../implementation-guide.md) 第 5、6、7、11、13 节和相关控件的测试。

1. 把目标转成可检查的条件，例如尺寸、字体覆盖、主题、实际状态、边界值、跨零角度、满量程、弹出行为和挂载恢复。
2. 优先复用真实 Gallery 演示与 `../ArcGallery/tools/docshots`。临时原生窗口探针采用本项目当前支持的宿主及公开 API，检查实际主题和 popup 能力；不照搬 AtomUI 的窗口模板限制。
3. 记录代码版本、SDK、配置、程序集路径与哈希、数据、窗口或图像尺寸及渲染比例。比较前后必须使用可比条件。
4. 明确捕获属于原生窗口、headless 渲染还是 RenderTargetBitmap。本项目 DocShots 使用 headless 绘图，不能称为操作系统原生截图。
5. 保留复现条件和默认动效；区分真实读数与动画位置。稳态对比先确认采样稳定，检测细小变化时校验采样分辨率；不套用外部固定等待时间或像素容差。
6. 对每个验收条件同时检查可观察状态和图像。人工打开关键截图；像素采样不能取代字体、缩放、裁切和语义检查。
7. 覆盖受影响的深浅色、字号或字重覆盖及尺寸。完整长页面验收必须检查目标所在视口；首屏图片不证明屏外内容完整。
8. 记录步骤、预期、实测、捕获方式和通过/失败。原生捕获不可用时说明使用的替代模式，不伪造原生验证。

查看 DocShots 的 `Program.cs` 或帮助确认当前参数：`page <Class> <lang> <out.png> [dark] [scroll=y|find=Name]`、`check` 和 `shoot`。不要把临时输出路径写进发布源码。

中间探针和日志放仓库外；面向用户保存的报告、截图和支撑资产放工作区交付目录。仅停止本次创建且已核对身份的进程；用户需要保留的预览继续运行。
