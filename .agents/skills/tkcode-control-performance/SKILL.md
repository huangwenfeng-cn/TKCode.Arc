# 控件性能

先读 [实施指南](../../implementation-guide.md) 第 6、7、10、13 节和目标控件的同类实现。

1. 写清慢操作、实例数量、触发频率、输入规模及主要指标。选择控件级或真实 Gallery 场景；不要套用 AtomUI 的实例数量、方法数量或耗时阈值。
2. 在同一 SDK、配置、程序集、数据、主题和动效条件下记录基线。需要冷启动结论时测独立进程，需要重复操作结论时说明预热和样本数。
3. 区分布局、绘制、绑定、事件、模板、动效和 Gallery 页面固定成本。关于 Avalonia 成本的判断要有当前版本的公开行为或测量证据，不继承外部技能的成本表和行号。
4. 优先复用不变的几何、文字布局和画刷，并按真正受影响的属性失效。避免 Render 内 I/O、无界缓存及每控件高频定时器。
5. 固定模板关系优先用主题与 TemplateBinding；代码创建子控件时采用本项目共享原语及 `ArcTokens.Bind`。不要引入 `BindUtils.RelayBind` 或私有 API。
6. 对惰性内容证明默认状态、首次使用、第二次使用、模板重建和卸载都正确。不得将“隐藏节点零成本”或“模板节点绝不能代码创建”作为未经本项目验证的硬规则。
7. 检查绑定优先级、应用覆盖、属性重入、状态所有者、动态主题、字体缓存和释放路径。与同级 `tkcode-resource-lifecycle` 一起处理生命周期影响。
8. 先做最小修改，再以相同方法测量并运行相关行为回归。无收益或证据不足时停止扩大改造，保留有证据的正确性修复，不自动回滚用户工作。

结果用 `指标 / 基线 / 修改后 / 样本与环境 / 结论` 表达。减少对象或订阅只证明结构成本变化；单次烟雾计时不证明百分比提速。不能为了稳定采样删去原始约束或关闭需验证的动效。

临时探针、日志和缓存放仓库外。需要用户保存的报告和图片放工作区交付目录；不把临时测量工程加入组件发布包。验证遵循 [明文规范](../../AGENTS.md)，普通控件不自动跑完整套件。
