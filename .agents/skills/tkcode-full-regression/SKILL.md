# 完整回归

先读 [明文规范](../../AGENTS.md) 的 Verify 段、[实施指南](../../implementation-guide.md) 第 13 节和相关仓库 AGENTS.md。

1. 明确“全量”包含的仓库、项目、目标框架、平台、发布模式和集成测试。没有执行浏览器、移动端或 Native AOT 时，完整桌面测试不涵盖它们。
2. 枚举当前实际测试项目和 CI 配置，以用户范围及真实影响面选择集合；不使用 AtomUI 的项目清单、默认集成测试排除项或不存在的脚本。
3. 普通控件采用精确 filter；只有明确要求或基础层广泛改动才扩大为完整项目/套件。修复先做相关定向测试，稳定后再做需要的完整验证。
4. 单次按项目顺序运行并保存日志和机器可读结果，避免两个全量实例争用资源。临时缓存和结果放仓库外。
5. 定期报告已完成项目、当前范围、失败和不确定性，遵循当前命令工具的后台通知机制；不照搬外部技能的轮询或固定等待规则。
6. 无进展先检查最后测试、实际进程和资源，不擅自终止其他会话的测试。需要停止本次进程时先核对身份。
7. 收集已执行项目的全部失败；按失败点做定向修复，不每修一项就重跑全量。
8. 最终汇总每个项目的总数、通过、失败、跳过、未执行及耗时；构建失败或未运行项目不能算作测试通过。

`dotnet test` 的目标、过滤器和输出参数按实际测试运行器核对。Gallery 的直接运行入口仅在其 AGENTS.md 指定的发现阶段问题下使用，保留相同范围并防止过滤器意外求交集。

只有所声明集合全部执行并有完成结果时，才称该范围的全量通过。不生成虚假的脚本 SUMMARY 行，也不因文档维护启动本技能。
